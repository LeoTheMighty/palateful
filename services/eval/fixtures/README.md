# Eval Fixtures

This directory contains test fixtures for evaluating recipe extraction strategies.

## Directory Structure

```
fixtures/
  text/            # Plain text inputs (e.g. OCR output)
  images/          # Image inputs (photos of recipes)
  urls/            # URL test configs (JSON with url field)
  expected/        # Ground truth JSON files
```

## Naming Convention

Fixtures are matched by filename stem. For example:

- `text/potato_quiche.txt` matches `expected/potato_quiche.json`
- `images/banana_bread.jpg` matches `expected/banana_bread.json`
- `urls/allrecipes_pasta.json` matches `expected/allrecipes_pasta.json`

## Image Fixtures

`images/` holds the inputs for the vision suite, which grades
`extract_recipe_from_image` (gpt-4o-mini vision). Each PNG is a **render of
the same-named text fixture**, so an image and its text twin describe the
same recipe(s) and share one `expected/<stem>.json`. That makes
`--compare text_extractor,vision_extractor` a true modality comparison
instead of two unrelated datasets.

The PNGs are committed and regenerated by
`scripts/generate_image_fixtures.py`:

```bash
poetry run python scripts/generate_image_fixtures.py                 # all
poetry run python scripts/generate_image_fixtures.py banana_bread    # one
poetry run python scripts/generate_image_fixtures.py --font /path/to/face.ttf
```

Layout is chosen per fixture in the script's `LAYOUTS` table:

| Style | Used for |
|---|---|
| `page` | one recipe on a single page |
| `facing_pages` | two recipes split by a page gutter |
| `cards_row` | two recipe cards side by side |
| `panels_row` | three panels on one sheet |

The multi-recipe styles exist to exercise the FR88 fan-out contract — the
extractor must emit one entry per distinct recipe. Multi-recipe cases are
tagged `multi_recipe` in `datasets/vision_extraction/manifest.yaml`, which
is what the `recipe_count_accuracy` gate keys off.

Two things to know before adding one:

- **Fonts.** The renderer picks the first face in `FONT_CANDIDATES` that
  exists locally, and hard-fails on any character it cannot render. This
  guard is not cosmetic: Pillow's bundled face has no `ñ`, and quietly
  rendering `jalape□o` would put a tofu box in the image while
  `expected/*.json` still promises `jalapeño`.
- **Cost.** Every case is a live vision call. Keep the set small.

To add an image fixture: write the recipe text under `text/`, add a
`LAYOUTS` entry, run the generator, add the expected JSON, then register
the case in the vision manifest. `tests/test_vision_fixtures.py` checks
the whole chain lines up.

These fixtures are consumed by the **Vision Extraction** suite
(`VisionExtractionEvaluator`), which grades `extract_recipe_from_image` at
a hard `recipe_count_accuracy >= 0.80` bar on `multi_recipe`-tagged cases.
See [the suite section in the eval README](../README.md#vision-extraction---suite-vision_extraction)
for the metric table, the gate, and how to run it.

## Adding a New Fixture

1. Place the input file in the appropriate subdirectory (`text/`, `images/`, or `urls/`).
2. Create a matching expected JSON file in `expected/` with the same stem name.
3. The expected JSON should follow the standard recipe extraction schema:

```json
{
  "name": "Recipe Name",
  "description": "Brief description",
  "prep_time_minutes": 15,
  "cook_time_minutes": 30,
  "servings": 4,
  "ingredients": [
    {
      "text": "2 cups all-purpose flour",
      "quantity": 2,
      "unit": "cups",
      "name": "all-purpose flour"
    }
  ],
  "instructions": "Step-by-step instructions as a single string."
}
```

## Running Evals

```bash
# Run text extraction eval against all text fixtures
npx nx run eval:run-fixtures

# Run with a specific strategy
npx nx run eval:run-fixtures -- --strategy text_extractor

# Compare multiple strategies
npx nx run eval:run-fixtures -- --compare text_extractor,ocr_then_text
```

## URL Fixture Format

URL fixtures are JSON files with the following structure:

```json
{
  "url": "https://example.com/recipe",
  "description": "Optional description of what this tests"
}
```
