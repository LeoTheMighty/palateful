# Story ptd-4 — `bin/perf-audit` + `tools/perf-budgets.yaml` + capture/assert

**Epic:** epic-perf-debug-tooling
**Status:** in-progress → review → done
**Owner:** /dev
**Started:** 2026-04-23

## Context

ptd-2 + ptd-3a + ptd-3b landed the 9 per-screen tests and each emits a
`PERF_AUDIT_CSV,<screen>,<endpoint>,<count>` sentinel via
`emitCsv()`. ptd-4 ties the loop together: a driver that runs every
test, collects the sentinels, and either captures a new budget
(`--capture`) or asserts observed counts vs a committed budget
(`--assert`).

## Implementation

### New files

- **`bin/perf-audit`** — bash driver.
  - Walks `app/integration_test/perf_audit/[0-9][0-9]_*_test.dart`
    files and runs each via `flutter test … -d flutter-tester`. Files
    are run **one at a time** — the flutter-tester device has a
    log-reader race that bites when multiple integration test files
    load back-to-back in a single invocation (see ptd-2 QA notes).
  - Tees stdout to a temp file, greps for `PERF_AUDIT_CSV,` sentinels,
    pipes the filtered set into `tools/perf-audit-diff.py`.
  - `--capture` writes `tools/perf-budgets.yaml` (overwrites).
  - `--assert` prints a per-screen diff table regardless of outcome
    (for CI job-summary context); exits non-zero only under
    `PERF_AUDIT_STRICT=1` — default warn-mode emits "warn-mode:
    violations ignored" and exits 0 so the 14-day grace window
    (ptd-5) doesn't fail CI.
  - `--help` prints the header docstring.
  - Exit codes: 0 success or warn-mode, 1 strict-mode violation or
    zero-sentinels-collected, 2 usage / tooling error.

- **`tools/perf-audit-diff.py`** — Python helper.
  - Reads CSV sentinels on stdin, aggregates into a
    `{screen: {endpoint: count}}` map.
  - `--mode capture` emits `tools/perf-budgets.yaml` with the captured
    per-screen `total` + sorted `endpoints` map.
  - `--mode assert` compares observed vs budget, renders a pipe-
    separated diff table on stdout, writes violations to stderr.
  - PyYAML is the only dep — already a dev dep via the api project.

- **`tools/perf-budgets.yaml`** — committed baseline. Generated by
  `bin/perf-audit --capture` and hand-editable for intentional raises.
  Contains 9 screens × 14 endpoints at time of commit:

| screen            | total | endpoints                                        |
| ----------------- | :---: | ------------------------------------------------ |
| activity_hub      |   1   | GET /v1/activities                               |
| books             |   1   | GET /v1/recipe-books                             |
| calendar          |   1   | GET /v1/meal-events                              |
| cook_mode_entry   |   2   | GET /v1/recipes/:id, GET /v1/users/me/notification-preferences |
| home              |   5   | GET /v1/cooking-logs, GET /v1/favorites, GET /v1/meal-events, GET /v1/meals, GET /v1/recipe-books |
| meals             |   1   | GET /v1/meals                                    |
| profile           |   1   | GET /v1/users/me                                 |
| recipe_detail     |   1   | GET /v1/recipes/:id                              |
| search            |   1   | GET /v1/search                                   |

## QA walkthrough

1. `bin/perf-audit --capture` — runs 9 test files (~120s wall),
   writes `tools/perf-budgets.yaml`.
2. `bin/perf-audit --assert` — same run, prints `all screens within
   budget` + diff table with `+0` deltas for every screen.
3. Add a duplicate `api.getFavorites()` call to
   `home_content_provider.dart`, re-run: diff table shows
   `home: 6 / 5 (+1 FAIL)`. Warn-mode exits 0; set
   `PERF_AUDIT_STRICT=1` and it exits 1. Revert the change.
